# 01 · 上传入口拦截伪 docx，失败文案归一

**状态**：ready-for-agent

## What to build

用户上传一个内容不是 Word 的文件（扩展名是 `.docx`，实际是文本/图片/其它压缩包）时：

- 在**上传阶段**就被拒绝，界面上看到「文件已损坏或不是有效的 .docx，请用 Word 重新另存后再上传」；
- 服务端**不留下**任何存储文件、也不留下 `t_paper_file` 记录；
- 排版失败时（其它解析类异常），错误文案不再出现重复的「排版失败：」前缀，也不出现 `ZipException`、十六进制签名等内部细节。

## Blocked by

无

## 验收标准

- **给定**一个文本文件改名为 `x.docx`，**当**调用上传接口，**那么**返回业务错误码 400、文案为「文件已损坏或不是有效的 .docx…」，且 `t_paper_file` 计数不变、存储目录无新增文件。
- **给定**一个正常的 `.docx`，**当**上传，**那么**返回成功并落库（回归保护，不得误伤）。
- **给定**一个 0 字节文件，**当**上传，**那么**仍返回「文件不能为空」（原有行为不退化）。
- **给定**一个会导致解析失败的文档，**当**排版失败，**那么** `error_msg` 中「排版失败」只出现一次，且不含 `Exception` / `0x` 等字样。

## 备注

- 魔数校验放在「非空 / 扩展名 / 大小」之后、`storageService.store` 之前。
- 测试接缝：`PaperService.upload`（MockMultipartFile），不启 Web 容器。
