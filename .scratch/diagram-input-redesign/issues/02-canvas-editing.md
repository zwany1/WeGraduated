# 票 02 · 画布直接编辑与回写

**status**: done（2026-10-29）
**Blocked by**: 01

## What to build

出图之后，用户能直接在画布上改，而不是回到表单里找字段：
拖动节点调整位置、双击节点改文案、拖拽连线改变连接关系；表单折叠为「高级设置」，
展开后字段数量与改造前一致（R6：一个字段都不删）。

画布上的任何改动都要能反向回到文本视图（R4 的前端侧）—— 这是最容易漏的一环，
漏了就会出现「画布改了、切回文本被覆盖回旧版本」。

## 验收标准

1. 给定一张已生成的时序图，当在画布上把某个参与者的名称从「系统」双击改为「认证服务」，
   那么切到文本视图时，文本中对应的参与者名称已变为「认证服务」。

2. 给定一张已生成的图，当拖动节点位置后保存并重新加载，那么位置被保留。

3. 给定任意一种图，当打开配置面板，那么表单默认处于折叠态；展开后字段数量与改造前相同。

4. 给定画布编辑后的图，当切换回文本视图再切回画布，那么画布内容与切换前一致（不丢改动）。

## 约束

- 不改变 X6 的渲染与 Dagre 布局算法（R9），只开启编辑交互。
- 导出（SVG / PNG / Mermaid）行为保持现状。

## 实施记录

**后端**：新增 `POST /diagram/dsl/render`（结构化配置 → 文本）。前端把画布改动落成配置后调它，
拿到规范文本回填输入框 —— 语法只在 `DiagramDslService` 一处，前端不实现第二份。
落点：`DiagramController.renderDsl` + `RenderDslDTO`；测试 `DiagramControllerRenderDslTest`
（含「用 Map 传配置」用例，锁住 Jackson 反序列化成 LinkedHashMap 后必须 convertValue）。

**前端**（`SystemDesign.vue`）：
- 双击节点/连线 → 原位浮出 `.inline-edit` 输入框（回车提交、Esc 取消、失焦提交），
  不用模态框，避免打断画布上下文；页面级 `position: fixed`，无需关心容器定位。
- 拖动结束（`node:moved`）→ 位置写回 `currentVO.nodes`，保存链路无需改动就带上新坐标。
- 时序图参与者拖动后 `syncSequenceGeometry()` 让生命线、激活条、消息端点一起跟随
  （自环消息额外重算 vertices）。
- 画布改名/改文案 → 更新 `seqConfig` → 300ms 防抖调 `dsl/render` → 回填 `seqDsl`。
- 面板折叠：`.adv-toggle` + `.adv-body`，默认收起。

**与验收标准的偏差（有意为之，需知会）**：
1. 验收 3 说「任意一种图」面板默认折叠 —— 本轮只对 SEQUENCE 生效。其余 7 种还没有文本入口，
   把唯一的输入源折起来等于页面不可用；随票 03–05 各自有了文本视图后逐图铺开。
2. 验收 2「拖动位置保存后仍在」只对**模型里带坐标**的图成立（SEQUENCE / SWIMLANE /
   ACTIVITY / USECASE / ER）。FLOW 与 CLASS 走 Dagre 重排，坐标不入模型（R9 不改布局）。
3. 时序图参与者只能横向移动（纵向自动弹回原位）；自由拖动可能让相邻参与者盒子贴在一起甚至重叠，
   这是用户自己控制的结果，不做强制吸附（吸附会把可拖动范围压得很小，反而像拖不动）。
4. 「拖拽连线改连接关系」本轮未做：时序图消息端点是坐标定位而非锚点，改连接等于改
   from/to，而表单里本来就有这两个下拉；节点型图的连线重连等票 03–05 一并处理。

**验证**：后端 53 个测试（新增 3 个）全绿；浏览器端到端 12/12（`e2e/scenarios/sequence-canvas.mjs`），
覆盖折叠、双击改名回写、文本往返不丢、拖动位置随保存落盘。
