# 票 03 · 流程图 + 架构图方言

**status**: done（2026-10-29）
**Blocked by**: 01

## What to build

复用票 01 的骨架，为 FLOW 与 ARCH 两种图各实现一种方言，前端文本入口对这两种图生效。

- **FLOW**：`开始 -> 提交论文` 这类顺序流；`[合格?]` 表示判断节点；
  `[合格?] -> 通过: 是` 表示条件分支。
- **ARCH**：缩进表示层级归属（顶层是层名，其下缩进的是该层组件）。

注意：FLOW / ARCH 后端已有 `DiagramGenerator` 的自然语言关键词解析入口（走 `description` 字段）。
本票要决定它与 DSL 的关系：**DSL 是主入口，自然语言入口保持现状不动**，两者不互相覆盖。

## 验收标准

1. 给定流程图文本
   ```
   开始 -> 提交论文
   提交论文 -> 格式检查
   格式检查 -> 合格?
   合格? -> 通过: 是
   合格? -> 退回修改: 否
   ```
   当以 `FLOW` 解析，那么产出 5 个节点，其中「合格?」为判断类型，「通过」「退回修改」
   两条边分别带 `是` / `否` 标签。

2. 给定架构图文本（缩进表示层级）
   ```
   表现层
     Vue3 前端
   服务层
     SpringBoot
     MySQL
   ```
   当以 `ARCH` 解析，那么产出 2 个层，第一层含 1 个组件、第二层含 2 个组件，层名与组件名正确。

3. 给定含语法错误的架构图文本（第二行缩进不一致），当解析，那么返回行号与片段。

4. 给定任一合法配置，当 render 后 parse，那么结构等价（往返一致）。

## 约束

- 不改动现有 `DiagramGenerator` 的自然语言解析能力与行为。

## 实施记录

**FLOW**：新增 `FlowConfig`（节点带 start/action/condition/end 类型 + 带标签的边）与
`FlowRuleEngine`（按拓扑 rank 分行、行内居中；前端 FLOW 仍走 Dagre，坐标只是兜底）。
方言：每行 `A -> B` 或 `A -> B: 条件`；名字带 `?`／`？` 或用 `[]`/`【】`包裹即判断节点；
`开始/start`、`结束/完成/end` 自动识别为起止节点；不含连接符的单行 = 孤立节点（不报错）。
明确拒绝「像箭头但打错了」的行（含 `>` `-` `→` 但没有合法连接符），避免把错字吞成节点名。

**ARCH**：`ArchitectureConfig` 复用现有引擎，只新增解析/反向生成。方言：顶格 = 层名，
缩进 = 该层组件；`@title` 给系统名。未归属的组件（还没写层就缩进）与同层缩进不一致都会报错。

**接线**：`DiagramController.generate` 解析成功后按配置类型分发（`FlowConfig` → flowEngine，
`ArchitectureConfig` → 现有 arch engine，`SequenceConfig` → seqEngine），并把 `dsl` + `config`
随结果回给前端（`attachDslInfo`），前端据此回填表单。

**与验收标准的不一致（有意）**：验收 1 写「产出 5 个节点」，但示例文本里是
开始/提交论文/格式检查/合格?/通过/退回修改 **6 个不同名字**。按「一个名字一个节点」
只能是 6，测试按 6 断言（`DiagramDslFlowArchTest`），节点类型与两条分支标签均按验收原意校验。

**前端**：流程图/架构图 tab 顶部加文本输入（示例、生成、行号报错），原自然语言描述与
逐层配置折叠进「高级设置」并保持可用；有文本时文本优先。架构图生成后用解析结果覆盖
逐层配置（层顺序与组件以文本为准），保证文本/表单/画布三者一致。

**验证**：后端 64 个测试全绿（新增 8 + 3）；浏览器端到端 9/9
（`e2e/scenarios/flow-arch.mjs`：判断菱形、是/否标签、三层架构、两类语法错误的行号定位）。
