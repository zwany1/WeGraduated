# 票 04 · 类图 + 用例图方言

**status**: done（2026-10-29）
**Blocked by**: 01

## What to build

为 CLASS 与 USECASE 两种图实现方言并打通前端文本入口。这两种是嵌套最深的图
（类：类 → 属性 / 方法 → 关系；用例：参与者 → 用例 → include / extend 关系），
正是「填字段繁琐」感受最强的两种。

- **CLASS**：`class 论文 {` 起头，成员行 `- 标题: String` 表示属性、`+ 提交()` 表示方法，
  关系行 `论文 -- 学生: 属于`。
- **USECASE**：`(学生): 提交论文, 查看进度` 声明参与者及其用例；
  `提交论文 -include-> 格式校验` 表示包含关系。

## 验收标准

1. 给定类图文本
   ```
   class 论文 {
     - 标题: String
     + 提交()
   }
   论文 -- 学生: 属于
   ```
   当以 `CLASS` 解析，那么产出 2 个类，其中「论文」含 1 个属性（标题 / String）
   与 1 个方法（提交），关系为「论文 → 学生」标注「属于」。

2. 给定用例图文本
   ```
   (学生): 提交论文, 查看进度
   提交论文 -include-> 格式校验
   ```
   当以 `USECASE` 解析，那么产出 1 个参与者含 2 个用例，且「提交论文」到「格式校验」
   为 include 类型关系。

3. 给定类图中方法行写成 `提交()`（缺 `+` 前缀），当解析，那么返回该行行号与片段。

4. 给定任一合法配置，当 render 后 parse，那么结构等价。

## 约束

- 属性与方法的可见性标记（`-` / `+`）必须能被区分，不可退化成无类型文本。

## 实施记录

**CLASS 方言**
```
class 论文 {
  - 标题: String        属性 = 可见性 + 名字 [+ 「: 类型」]
  + 审核(): boolean     方法 = 可见性 + 名字 + () [+ 「: 返回类型」]
}
论文 -- 学生 [1 n]: 属于  关系 = A 箭头 B [基数] [: 关系名]
```
- 箭头：`--` 关联 / `<|--`、`--|>` 继承 / `*--` 组合 / `o--` 聚合（正则里长箭头必须排在 `--` 前面）
- 成员缺可见性前缀 → 带行号报错并给出片段（验收 3）；若其实是关系行忘了写 `}`，提示里也会点出来
- 关系另一端没声明的类会**自动补成空类**（验收 1 的「2 个类」正是这样来的：只声明了论文，关系里出现学生）

**模型上的唯一改动**：`ClassConfig.ClassRelation` 增了 `label`（关系名）。原来只有 source/target/type/left/right，
「属于」这种关系名无处安放。引擎把标签拼成「左基数 右基数 关系名」；前端 CLASS 边标签改为
「先按基数特征分流，剩下的当中文名放中间」，纯基数场景（旧数据）行为不变。

**USECASE 方言**
```
(学生): 提交论文, 查看进度     参与者 + 关联用例（生成 association）
(教师)                        只有参与者也可以
提交论文 -include-> 格式校验
审核论文 -extend-> 提交论文
学生 -> 提交论文              普通关联
```
- 关系端点按「已声明的参与者 → 用例」顺序解析，未声明的自动建成用例
- include / extend 的箭头在反向生成时原样还原

**前端**：两个 tab 顶部加文本输入，逐类/逐项配置折叠进「高级设置」；文本生成成功后
用解析结果覆盖 `clsConfig` / `ucConfig`，保证文本与表单说的是同一件事。

**验证**：后端 72 个测试全绿（新增 8）；浏览器端到端 9/9（`e2e/scenarios/class-usecase.mjs`）。
