## What to build

为 CLASS 与 USECASE 两种图实现方言并打通前端文本入口。这两种是嵌套最深的图
（类：类 → 属性 / 方法 → 关系；用例：参与者 → 用例 → include / extend 关系），
正是「填字段繁琐」感受最强的两种。

- **CLASS**：`class 论文 {` 起头，成员行 `- 标题: String` 表示属性、`+ 提交()` 表示方法，
  关系行 `论文 -- 学生: 属于`。
- **USECASE**：`(学生): 提交论文, 查看进度` 声明参与者及其用例；
  `提交论文 -include-> 格式校验` 表示包含关系。

## 验收标准

1. 给定类图文本
   ```
   class 论文 {
     - 标题: String
     + 提交()
   }
   论文 -- 学生: 属于
   ```
   当以 `CLASS` 解析，那么产出 2 个类，其中「论文」含 1 个属性（标题 / String）
   与 1 个方法（提交），关系为「论文 → 学生」标注「属于」。

2. 给定用例图文本
   ```
   (学生): 提交论文, 查看进度
   提交论文 -include-> 格式校验
   ```
   当以 `USECASE` 解析，那么产出 1 个参与者含 2 个用例，且「提交论文」到「格式校验」
   为 include 类型关系。

3. 给定类图中方法行写成 `提交()`（缺 `+` 前缀），当解析，那么返回该行行号与片段。

4. 给定任一合法配置，当 render 后 parse，那么结构等价。

## 约束

- 属性与方法的可见性标记（`-` / `+`）必须能被区分，不可退化成无类型文本。
