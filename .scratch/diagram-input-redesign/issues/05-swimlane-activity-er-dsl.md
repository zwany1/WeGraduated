# 票 05 · 泳道图 + 活动图 + ER 图方言

**status**: done（2026-10-29）
**Blocked by**: 01

## What to build

补齐最后三种方言：SWIMLANE / ACTIVITY / ER，前端文本入口对这三种生效。
至此 8 种图全部支持文本输入。

- **SWIMLANE**：泳道名后跟冒号，其下缩进的行为该泳道内的节点。
- **ACTIVITY**：与流程图共用顺序记号，另需支持分支 / 合并的表达。
- **ER**：实体与关系，基数用 `1--N` 这类记号表示。

注意：ER 图在系统图页内有 tab，另有独立页 `/er`，两者是**两套独立实现**。
本票只改系统图页内的 ER tab，独立页不在范围内（入口合并见 Out of Scope）。

## 验收标准

1. 给定泳道图文本（泳道名 + 缩进节点），当以 `SWIMLANE` 解析，
   那么泳道数与各泳道内节点数与文本一致。

2. 给定活动图文本含一处分支与一处合并，当以 `ACTIVITY` 解析，
   那么产出对应分支节点与合并节点，且边连接正确。

3. 给定 ER 文本含一对多关系 `学生 1--N 论文`，当以 `ER` 解析，
   那么产出 2 个实体与 1 条关系，基数标记为一到多。

4. 给定三种图各自的任一合法配置，当 render 后 parse，那么结构等价。

5. 给定 8 种图各自的示例文本，当逐一解析，那么**全部成功**（全量回归，证明 8 种方言都通）。

## 约束

- 不改 `/er` 独立页。

## 实施记录

**SWIMLANE / ACTIVITY 共用一个骨架** `readLanes()`：顶格 `泳道名:` → 泳道；缩进行 → 该泳道节点；
顶格 `A -> B [: 条件]` → 连线。两种图只差在 Config 与节点类型词表
（泳道 start/task/gateway/end，活动 START/ACTION/DECISION/END）。

- SWIMLANE 要求节点必须写在泳道下（连线里出现未入泳道的节点 → 带名字报错）
- ACTIVITY 是流程图式写法：可以完全不分泳道（自动归入「主流程」），节点也能**由连线引入**
  —— 这一条是踩坑点：只认缩进行时，`开始 -> 提交` 这种纯连线文本会被判「没有内容」

**ER**：走的是另一条链路 —— `ErDTO` + `ERGraphService`（Chen 记法），不是 DiagramVO。
方言：`实体 (属性1, 属性2*)`，属性带 `*` 为主键；`A 1--N B: 关系名`，两端基数拼成 `1:N`。
ER 的 `ErDTO` 没有标题字段，遇到 `@title` 直接报错说明原因，而不是静默丢弃。

**接线**：`DiagramController` 注入 `ERGraphService`，ER 分支直接返回 `ERGraphVO`；
SWIMLANE/ACTIVITY 走各自引擎并回传 dsl+config，前端据此覆盖「高级设置」。

**连带调整**：8 种图全实现后，「尚未开放」分支对受支持类型不再可达，
三条把它当断言的旧测试改成「根本不存在的类型要被明确拒绝」。

**验证**：后端 80 个测试全绿（新增 8）；浏览器端到端 18/18，含
「8 种图示例文本逐一生成」的全量冒烟；另外三个场景回归 12/12、9/9、9/9。
