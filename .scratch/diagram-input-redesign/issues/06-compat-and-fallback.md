# 票 06 · 存量数据兼容与降级通道

**status**: done（2026-10-29）
**Blocked by**: 01

## What to build

保证改造不抛弃任何既有用户数据，并保证新交互有退路。

1. **存量兼容**：老图只存了结构化配置、没有 DSL 文本。打开时用 `render` 反向生成回填输入框。
   `render` 也失败（配置残缺）时，输入框留空但表单照常可用，**绝不阻断编辑**。
2. **降级通道**：DSL 解析失败或用户不愿写文本时，展开表单仍能完成全部配置，
   生成链路与改造前完全一致。
3. **表单折叠**：所有图的高级字段默认折叠（R6），展开后字段数量与改造前一致。

## 验收标准

1. 给定一张改造前保存、只含结构化配置的图，当加载，那么输入框被 `render` 结果填充，
   且画布渲染结果与改造前一致。

2. 给定一张配置残缺到无法 `render` 的老图，当加载，那么页面不报错、输入框为空、
   表单可正常展开编辑并保存。

3. 给定一段解析失败的 DSL，当点击展开表单，那么可以用表单完成配置并成功生成图。

4. 给定改造前保存的所有图，当逐一加载，那么**没有一张因缺少 DSL 字段而加载失败**。

## 约束

- 存量数据一律不得迁移时改写原配置，只能在读取时按需回填。

## 实施记录

**先说一个前提缺口**：这个页面原来**只有保存、没有打开入口** —— `save` 往磁盘写
`{storage}/diagrams/{userId}_{id}.json`，`list/load` 接口只被自由绘制页用过。
所以票 06 先补了一个「打开」对话框（列表 + 点选打开），否则"加载老图"无从谈起。

**配置必须无条件随图落盘**（`attachDslInfo` 改名前的语义是「只有文本路径才挂 config」）：
图存到磁盘后只剩 `DiagramVO`，不带 config 就永远没法反向生成文本。现在纯表单路径也会挂 config，
只有 `dsl` 原文仍限文本路径（避免纯表单被误认为"来自文本"）。

**打开一张图的三级降级**（`applyLoadedVo` → `backfillDsl`）：
1. 有 `dsl` 原文 → 直接填输入框；
2. 没原文但有 `config` → 调 `POST /diagram/dsl/render` 反向生成；失败就留空；
3. 两者都没有（改造前的老图）→ 留空，画布照常渲染、表单照常可编辑，不弹错。

**表单折叠**已在票 02–05 逐个 tab 落地：8 种图的高级字段默认收起，展开后字段数量与改造前一致。

**验证**：后端 80 个测试全绿；浏览器端到端 10/10（`e2e/scenarios/compat-load.mjs`），
其中真的往 `backend/data/storage/diagrams/` 写了一份「只有 nodes、没有 config/dsl」的
老格式 JSON 来验证打开不失败；四个既有场景回归 12/12、9/9、9/9、18/18。

**同批顺带**（用户反馈）：泳道图/活动图的背景方框重做 —— 原来是淡蓝底 + 绿色虚线 + 圆角块，
现在改为白底 + 极浅墨线直角 + 顶部表头细线 + 居中标题；节点也由圆角气泡改直角墨线；
这两个图还加了「允许缩小以看全整张图」的自适应（原来泳道表头会被裁在视口外）。
