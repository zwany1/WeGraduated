# 工程约定与踩坑记录

> 只记录「已经造成过实际问题」的规则，不写通用编程常识。

## 1. 测试不许依赖未入库的绝对路径

**踩坑**：`PaperServiceUploadTest` 最初用 `Paths.get("D:/project/Graduated/tmp_v3/edge/e1_normal.docx")` 读样本，而 `tmp_v3/` 从未被 git 跟踪。换机器或 CI 上 `mvn test` 直接 `NoSuchFileException`，那条「真 docx 仍能上传」的回归保护实际等于没有。

**规则**：
- 测试样本要么用代码现场造（POI / 临时目录 / 内联字节），要么放进 `src/test/resources/` 并走 classpath。
- 测试里出现 `D:/`、`C:/Users/` 这类机器相关前缀，一律视为缺陷。
- 计数类断言按 `userId` 等业务维度过滤，不用 `selectCount(null)` 统计全表。
- 测试写入磁盘的文件，在 `finally` 里删掉，别让 `mvn test` 往存储目录堆垃圾。

## 2. 「唯一判定点」必须配一条接线测试，并验证它会变红

**踩坑**：票 02 把结构评级收敛到 `FormatReport.evaluateStructure()`，但纯模型单测只能证明「方法算得对」，证明不了「`PaperService` 真的调了它」。把调用那行删掉，两个测试类依然全绿 —— 功能静默消失，前端只会安静地回退旧渲染。

**规则**：
- 凡是被 spec 声明为「唯一判定点 / 唯一调用点」的逻辑，必须有一条**端到端或半端到端**测试，断言结果真的落到了持久化产物上（如任务报告 JSON 里的字段）。
- 写完这条测试后，**手动把调用摘掉跑一次**，确认它变红。没变红的测试不算数。
- 本次记录：摘掉调用后日志出现「结构评级 null」，用例 FAILURE；恢复后 22 个测试全绿。

## 3. 收紧输入校验时，检查是否让既有错误分支变成不可达

**踩坑**：票 01 给 `upload` 加 ZIP 魔数校验后，**加密的 docx 被误判为「文件损坏」**。加密 Office 文档是 OLE2/CFB 容器（`D0 CF 11 E0`），不是 zip，于是上传阶段就被拒。而引擎的 `friendlyFormatError` 里那条「文档已加密，请用 Word/WPS 另存为不带密码的 .docx」因此永远走不到，用户按提示「另存为」却仍带密码，就陷入死循环。

**规则**：
- 在入口加格式/类型校验前，先搜一遍**下游已有的错误分类与文案分支**，确认新校验不会把它们变成死代码。
- 对合法的「例外形态」要单独识别并给出对应文案（如 OLE2 → 加密），不要统一归到「损坏」。
- 判定文件类型时优先用可证明的特征（魔数 + 容器内条目），只比 4 字节魔数会漏掉「真 zip 但不是 Word」的情况 —— 若决定只比魔数，就要在 spec 里写明这是有意的取舍。
