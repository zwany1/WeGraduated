# 后续优化清单

下次再决定是否实施。

## 五、功能完善（后端缺口驱动，工作量较大）

1. **排版后生成 PDF + 下载** — schema 有 `pdf_path` 字段但无生成/下载端点，用户期望直接出 PDF 而非 docx
2. **通知实时推送** — 现仅 polling（list/unread-count），排版完成 / 被邀请 / 反馈被回复无法即时感知，缺 SSE/WebSocket
3. **团队角色分级 + 所权转移** — 现仅 owner/member 两级，无 admin/editor/viewer 中间层，无法委派他人管理或只读协作
4. **GitHub OAuth 登录** — schema 有 `github_id`/`github_login` 字段、WebConfig 预留 `/auth/**` 排除路径，但无任何 OAuth Controller/Service 实现
5. **模板市场评论 / 反馈墙用户互动** — 市场只能评分、反馈墙只有管理员单向回复，无用户间评论/点赞/@

## 六、移动端响应式

1. **NavBar 移动端汉堡菜单** — `@media(max-width:900px)` 直接 `display:none` 隐藏导航，移动端无导航可点
2. **TemplateConfig / FormatTask / AdminLayout 响应式适配** — 固定侧栏 + 宽表格在小屏不可用：TemplateConfig 固定 180px 侧栏挤压主区、FormatTask 操作列 360px fixed right 横向溢出、AdminLayout 固定 248px 侧栏占满小屏

## 附：调研中发现的纯运维项（非用户直接感知，供参考）

- 限流/撤销 token/验证码/SSE emitters 全内存（`ConcurrentHashMap`），多实例与重启即失效，无 Redis
- 风控表 `t_risk_event` 已建表但无 Java 实体/Service/调用，设备指纹+风险评分未落地
- `/health` 仅返回 `{status:UP}`，无 DB/磁盘/队列深度依赖检查
- `DiffItem.page/x/y` 恒为 0/0.05 占位，未算真实 PDF 页码坐标（影响"点击差异跳转 PDF 位置"）
- 反馈图片以 base64 存 `LONGTEXT`，未走对象存储，撑大数据库与备份体积
