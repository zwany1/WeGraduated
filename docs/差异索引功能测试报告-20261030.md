# 差异索引功能测试报告

- 日期：2026-10-30
- 被测对象：`GET /api/paper/diff/{taskId}`（`DiffService`）+ 前端「排版前后对比」差异索引面板
- 测试样本：`2253400404 廖彦伊_改.docx`（1.83MB，723 段 / 非空 577 / 3 表 / 30 图 / 25386 字）
- 环境：后端 13355（dev profile）、前端 5173、Chrome 155 headless + CDP

## 一、测试范围与场景

**在范围内**：差异数据的构建（配对、字段比对、取值归一）、接口契约（鉴权/越权/异常）、索引的展示与交互（分组/排序/折叠/筛选/定位）、重复调用与换模板重排后的一致性。

**不在范围内**：排版引擎本身的格式落地（另有专项报告）、docx 渲染保真度（另有门禁 `preview-fidelity.mjs`）。

| 场景类别 | 覆盖方式 |
| --- | --- |
| 正常输入 | 真实论文 × 校规A4 版式，515 条差异 |
| 空数据 | 空文档排版（0 段）、无差异任务 |
| 重复项 | 6 处「本章小结」、2 处重复签名行、表格内重复值（同一行多个 `10`） |
| 大规模数据 | 577 段 / 30 图 / 3 表，515 条差异 |
| 异常输入 | 损坏 docx、0 字节文件、.txt 伪装、非法 taskId、越权、未登录、产物缺失、任务未完成 |

## 二、关键行为定义

| 行为 | 判定方式 |
| --- | --- |
| **索引构建正确性** | 序号 1..N 连续；每条 text/type/change 非空；变更描述左右值不得相同（伪差异）；类型收敛到 9 类枚举 |
| **取值准确性** | 索引声称的"变更后值"必须与产物 docx 里该段的实际 XML 值一致（抽样核对） |
| **增量更新** | 换模板重排生成新任务后，差异按新产物重算，不复用旧结果 |
| **一致性 / 幂等** | 同一 taskId 连续调用，响应逐字节相同；前端多次打开-关闭结果不变、不累积 |
| **重复项区分** | 同名/同值段落必须能通过位置标识区分，位置集合不得重复 |
| **边界容错** | 任何异常输入都不得返回 5xx；返回明确业务码与可读提示 |

## 四、缺陷清单

### DEF-1（已修）非法 taskId 返回 500

- 用例：E1b
- 现象：`GET /api/paper/diff/abc` 返回 HTTP 500「系统繁忙」，实际是路径参数类型错误
- 影响：监控/日志里表现成服务故障，掩盖真实原因
- 修复：`GlobalExceptionHandler` 增加 `MethodArgumentTypeMismatchException` → code 400「参数格式错误: taskId」
- 验证：修复后 HTTP 200 + code 400

### DEF-2（已修）表格内重复值的位置标识撞车

- 用例：C1
- 现象：表 3 里 5 个 `0`、8 个 `10` 并列出现，位置都标成「表 3」，用户仍无法区分，观感就是"重复条目"
- 修复过程（两次迭代）：
  1. 「表 N」→ 仍撞车（同表多行重复）
  2. 「表 N 第 M 行」→ 仍撞车（**同一行多个单元格值相同**，如表 3 第 2 行有两个 `10`）
  3. 最终「表 N 第 M 行 第 K 列」→ 通过
- 验证：9 组同名文本的位置集合全部互不相同

## 五、覆盖边界（设计限制，非缺陷）

| 编号 | 边界 | 说明 | 产品建议 |
| --- | --- | --- | --- |
| OBS-1 | **分页变化不在索引内** | 原稿 9 页 → 产物 15 页（新增 11 处分页），但索引里没有"分页"类型条目——`DiffService` 只比字号/字体/加粗/行距/对齐/缩进/段前距/段后距 8 项 | 若用户关心"页数为什么变了"，需在报告里补一条"分页变化 N 处" |
| OBS-2 | 只比文本相同的段落 | 整段被改写/合并时无法定位到具体段落，只有内容级总量提示（段落数/图片数） | 已知限制，已在前端 `title` 与报告中说明 |
| OBS-3 | 表格差异量大 | 117 条单元格级差异（对齐/字号），真实但对用户价值低 | 已按类型分组 + 折叠；如需再降噪可按表聚合成 1 条 |

## 六、未执行项（建议下一轮补）

1. **并发压力**：多用户同时请求 diff（当前单机单实例，未做并发压测）。
2. **超大规模**：>1500 段的文档，验证耗时与前端渲染。
3. **合并单元格的列号准确性**：`colNo` 按 `getTableCells()` 计数，合并单元格会与实际列号偏移（不影响区分，但文案可能与视觉列不符）。
4. **跨版本兼容**：历史任务的 report/diff 数据里没有 `where` 字段，前端已用 `v-if` 兜底，但未用旧任务实测。

## 七、结论

- 差异索引的核心链路**可信**：构建正确（无伪差异、序号连续、类型收敛）、取值准确（抽样与产物 XML 一致）、重复项可区分（精确到单元格）、幂等（三次调用逐字节相同）、异常输入不崩（10 类异常全部给出明确业务码）。
- 本轮修复 2 个缺陷：非法参数 500、表格重复值位置撞车。
- 性能：515 条差异生成中位 **842ms**，满足"点开即看"。
- 建议优先补 OBS-1（分页变化提示），它是用户最容易产生疑问的地方。
