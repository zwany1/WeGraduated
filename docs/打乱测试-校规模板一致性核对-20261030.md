## 三、原因分析

### 3.1 主因：段级乱序使"前置区/正文区"判定失效

`StructureDetector` 用「**是否已经遇到过第一个合法的一级标题**」来切分前置区与正文区：

```java
chapterStarted = false;              // 未遇到第一章
...
item.setFrontMatter(!chapterStarted);   // 还没遇到第一章 → 全当前置内容
```

而排版主流程对前置内容直接跳过（`if (item.isFrontMatter()) continue;`，前置区不改图表题注、不套正文规则）。

段级乱序把第一章标题（"绪论"）推到了文档中部，于是**它之前的所有块都被当成"前置内容"**，完全不做排版——这正好解释了为什么 S2 里出现连续的未处理段落（段 170-183 一片）。

章级乱序不触发该问题，因为每章整体移动、第一章仍在接近开头的位置，`chapterStarted` 很快为真。

### 3.2 次因：题注与图片被拆散后，题注退化为正文

`CaptionFormatter` 判定题注的前提是"与图片/表格相邻"：

```java
if (!adjacentToFigure(elements, i)) {
    stats.orphanCaptions++;   // 不相邻 → 不算题注，不参与编号
    continue;
}
```

段级乱序把图注和图分开后，这些题注不再被识别为题注，进而在正文格式化阶段被套上 `firstLine=480`（正文缩进）。字体字号仍是 10.5pt，是因为前置的 `figure` 样式处理已经生效——形成了"字号对、缩进错"的混合状态。

### 3.3 表题注段后距 160 twips 与配置不一致（两个样本都有）

`table` 规则里 `spaceAfter = 0`，但产物中表题注带 `spacing after="160"`（8pt）。这是引擎为了让表题与表格之间留白而**刻意加的处理**，不是随机误差；但它确实与模板配置不符，属于"引擎内部约定覆盖配置"。

### 3.4 附录居中不是缺陷

核对表里 `附  录` 的对齐是居中，而 `heading1.align = left`，看似不一致；实际 `pageConfig.section.appendixAlign = "center"` 明确要求居中，谢辞同理。属于**配置正确落地**。

## 四、结论

1. **章级乱序（S1）下，产物与模板配置 100% 一致**：正文 208 段、标题 75 个、题注 21 个逐项比对全过；纸张、页边距精确。
2. **段级乱序（S2）下出现 21 处不一致**，但它反映的是**引擎对"文档结构被打散"的鲁棒性不足**，而不是"没按配置排版"：
   - 4 个标题 + 8 个正文段**完全没排版**（根因：`chapterStarted` 判定失效，被当作前置内容跳过）
   - 6 个图题被加了正文缩进（根因：图注与图被拆散，题注识别失效后退化为正文）
   - 1 个表题缺字体 + 表题注段后距 160 与配置不符（引擎内部约定覆盖了 `spaceAfter=0`）
3. 真实用户不会把论文段落随机打散，所以 S2 的问题**不影响正常使用**；但它是明确的鲁棒性缺陷——如果用户原稿本身章节标题不规范（例如一级标题没套 heading 样式），同样会触发"整段不排版"。

## 五、建议

| 优先级 | 建议 | 依据 |
| --- | --- | --- |
| **P0** | 前置区判定不要只依赖"遇到第一个一级标题"，补充兜底：若文档过半仍未出现一级标题，按"目录结束"或"第一个正文特征段"切分 | S2 有 29 个块因此完全没排版 |
| **P1** | 题注识别在"与图不相邻"时，再给一次机会：若段文本形如「图X-Y 标题」且字体为 figure 配置，仍按题注处理（不加正文缩进） | 6 个图题被加了 480 缩进 |
| **P2** | 表题注的 `spaceAfter=160` 要么写进 table 规则，要么在报告中说明 | 两个样本均不一致 |
