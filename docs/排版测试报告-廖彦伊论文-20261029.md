## 一、结论摘要

1. **引擎的格式落地是准的**：标题/正文的字体、字号、加粗、对齐、段前段后、固定/倍数行距在三套版式下逐段核对，二级/三级标题 100% 合规，正文 98% 合规，A4/B5 纸张与页边距在 `sectPr` 里正确写入。
2. **真正的问题集中在"结构被破坏之后"**：一旦「参考文献」标题不在文末，它后面的所有内容会被当成文献条目处理——多段被合并成一段（文字粘连）、图片被吞掉、悬挂缩进错乱。S2 因此丢失 5 张图。
3. **浏览器预览不是产物的忠实呈现**：纸张宽度恒为 900px、无分页、正文字体被强制成雅黑、标题字号/加粗不跟版式走、题注与公式的居中被强制左对齐。**用这个预览验收"字体/分页"会得出错误结论。**
4. **目录是原稿静态文本**：页码仍是原稿页码，换版式/打乱后完全不成立。（初版曾判断"目录每条自带段前分页、成品会被拉成 48 页"，复核后确认为统计口径错误——目录条目的 `pageBreakBefore` 全部是 `w:val="0"` 显式关闭，见 P2 撤回说明。）

## 二、排版问题清单（按严重度）

### 🔴 P1 参考文献之后的正文被当成文献条目：段落被合并、图片丢失

- **位置**：S2 产物 `t322` / `t327` / `t328`，第 331 段「参考文献」之后（第 332–496 段）
- **现象**：第 343 段一个 run 里粘了 8 段原文——`(1) 手动控制功能…复位控制。图3-1按钮选型图各层之间通过标准工业信号连接…系统设计目标与原则启动仿真：测试用例设计与执行软件平台与开发环境步骤与预期：…变量自动同步：…`；pPr 被改成悬挂缩进（`left=640 / firstLine=-640`），字号 21（10.5pt），行距 360 auto。
- **图片丢失 5 张**（30 → 25）：`图3-1按钮选型图`（原 290 段）、`图4-1定位器IO线路接线图`（原 350 段）、`如图6-2`（原 490 段）、`如图6-4`（原 518 段）、`如图6-5`（原 520 段）——对应的 `rId18/19/29/31/32` 在产物中已不存在，段落文字仍在。
- **原因**：`ReferenceFormatter` 从「参考文献」标题一直处理到「附录/致谢」标题，中间所有段都按"条目续行"合并（`REF_ITEM_START` 不匹配即并入上一条），合并时只保留文字、丢弃 `w:drawing`。
- **影响**：正文段落边界消失、图丢失、缩进错误——**内容级损坏，且任务状态仍显示"已完成"**。
- **建议**：文献区范围改为"到下一个标题级段落 / 到附录/致谢/声明"为止，并限制合并只发生在"上一条以标点结尾且本条不像正文"的情况下；合并时若段落含 `w:drawing`/`w:oMath` 一律不合并。

### 🟠 P3 版式 C 的「首行缩进 0」不生效

- **位置**：`t324`（原稿+版式C）、`t326`（S1+版式C）、`t328`（S2+版式C），正文 248/249 段
- **现象**：模板配置 `body.firstLineIndent=0`，产物仍写 `w:ind w:firstLine="480"`（2 字符），预览里也能看到每段仍缩进 2 字。
- **对照**：同批次的字体（宋体）、字号（21=10.5pt）、行距（240 auto=单倍）都正确落地，只有缩进没变 → 不是整条规则失效，而是"0 被当成未配置"。
- **建议**：区分"未设置(null)"与"显式 0"，显式 0 时写 `w:firstLine="0"` 并去掉 `firstLineChars`。

### 🟠 P4 「参考文献 / 附录」标题不吃模板标题规则

- **位置**：`t323/t324`（版式 B/C）第 514 段「参考文献」、第 526 段「附  录」
- **现象**：仍是黑体 14pt、无段前段后、行距沿用原稿（`lineRule` 缺失）；版式 B 要求 16pt 加粗居中、版式 C 要求 15pt 加粗左对齐，都没套上。`t320` 里这两段还多了一个原稿的「加粗」。
- **原因**：`SectionFormatter` 对"参考文献/附录/谢辞"走独立分支，只设字体/对齐/分页，没复用 heading1 规则。
- **建议**：特殊章节标题复用 heading1 的字号/加粗/间距，仅保留"另起一页 + 各自对齐方式"的差异。

### 🟠 P5 三线表没有生效：表格仍是"每行一条横线"

- **位置**：3 张表（原稿第 309/337/509 段），产物 `t320–t328` 全部一致

- **建议**：`TableFormatter` 统一重写 `tblBorders`（只留 top/bottom/insideH=header 下一条），并清掉单元格级 `tcBorders`。

## 三、浏览器预览保真度专项（本次最需要修的一块）

> 预览是用户验收排版结果的唯一界面，但它目前**不能用来验收字体、对齐和分页**。

| # | 问题 | 实测证据 | 影响 |
| --- | --- | --- | --- |
| V1 | **纸张宽度恒为 900px** | A4/B5 三套版式 `section` 宽度都是 900px（`pageWidth:900`），`ignoreWidth:true` + `breakPages:false` | 分不清 A4 与 B5；页边距完全看不到 |
| V2 | **没有分页** | 全文渲染成 3 个超高 `section`（最高 27774px），无页边界 | 无法验收"每章另起一页"、孤行、表格跨页；P2 的 48 页目录在预览里"看不出来" |
| V3 | **正文字体被强制成雅黑** | 正文 span `font-family: Arial, "Microsoft YaHei", sans-serif`（`normalizeVisibility` 里 `!important`），而标题仍是 `黑体`、题注仍是 `"Times New Roman", 宋体` | 宋体/仿宋差异不可见；同一页出现"雅黑正文 + 黑体标题 + 宋体题注"三种字体 |
| V4 | **标题字号/加粗不跟版式** | 版式 B 要求黑体 16pt 加粗，预览里是 `18.67px(=14pt)`、`font-weight:400`；版式 C 要求 15pt，预览也是 14pt | 三套版式的标题在预览里长得一样，只有行距和正文字号在变 |
| V5 | **对齐被强制左对齐** | 内联 `text-align:justify/center`，计算值全部 `start`（`DocxCompare.vue` 的 `:deep(.docx p){text-align:start!important}`） | 题注不居中（`clip_caption.png`）、公式不居中、两端对齐不可见 |
| V6 | **200% 缩放后内容被裁切** | 放大后页面超出容器，左右两侧文字被切掉，只能横向拖（`zoom_table.png`） | 想看清字号/缩进时反而读不全 |

**行距倒是准的**：版式 A `line-height:26.67px`（=20pt 固定）、B `24px`（1.5 倍）、C `16px`（单倍），与产物一致。

> **2026-10-29 更新**：上表 V1–V6 已全部修复（双模式预览、真纸宽+页码、按文档字体+缺字形兜底、对齐按段降级、标题跟随版式、CSS zoom 缩放），并补上了 V2 的关键缺口——**段落级「段前分页」现在也会切页**（docx-preview 只认样式级分页，前端在解析树里补注分页符，见 `.scratch/preview-fidelity/issues/07-page-break-before.md`）。门禁 `node e2e/scenarios/preview-fidelity.mjs` 共 8 项断言全绿。
>
> 复核中还发现一个**遗留的预览侧小缺陷**（与本次改动无关，修复前就存在）：「摘要→Abstract」「目录→绪论」之间会多出一张全白页——docx-preview 对 `sectPr` 节边界的 `pageSize` 有无不一致时会多切一次页（`groupByPageBreaks` 的 `isPageBreakSection(prev, next)` 在 props 缺失时也判为换页）。Word 里没有这两张白页。已记录为待办，不影响版式验收。

**建议**（按性价比）：① 去掉 `ignoreWidth`、按 `pgSz` 设纸宽；② 开 `breakPages:true` 画分页线；③ `normalizeVisibility` 只在检测到"缺字形/全白"时改字体，不要无差别覆盖；④ 标题的 `font-size/weight` 以内联 `!important` 兜底；⑤ `text-align` 只对确实出现大间隙的段落降级，不要整篇覆盖。

## 五、打乱方式与复现

```bash
# 1) 解析 + 生成两个乱序样本（章级 / 段级，含注入公式）
python tmp_v4/extract.py tmp_v4/orig/orig.docx > tmp_v4/outline.json
python tmp_v4/shuffle.py            # -> s1_chapter_shuffle.docx / s2_block_shuffle.docx

# 2) 克隆两套版式（B5/仿宋/1.5 与 A4/五号/单倍）
node tmp_v4/make-templates.mjs      # -> template 103 / 104

# 3) 真实浏览器：上传 3 个样本 → 选方案 → 批量排版
node tmp_v4/ui-upload.mjs

# 4) 浏览器内逐个任务预览 + 分段截图（含放大/裁剪截图）
node tmp_v4/preview.mjs
node tmp_v4/probe-styles.mjs        # 采集计算样式（字体/行距/缩进/对齐）
node tmp_v4/clip-shots.mjs          # 题注/表格/公式的 2~3 倍局部图

# 5) 产物 XML 级核对
python tmp_v4/verify.py             # 按模板规则算合规率，列出违规段落
```

- **乱序规则**：S1 以 9 个一级标题为界整体重排（保持章内顺序），S2 对第 168–586 段做整体随机（种子 777），表格、节属性、图片关系不动；S2 额外插入 1 个 OMML 公式（原文无公式，用于覆盖"公式"要素）。
- **说明**：9 个任务中 3 个由浏览器 UI 提交（t320–t322），其余 6 个（t323–t328）通过"换模板重排"背后的同一接口 `POST /paper/format` 提交——页面上的「换模板」弹窗里的 `el-select` 对 CDP 合成点击无响应，为不影响排版验证改用接口提交；**预览与截图全部在浏览器里完成**。
- **环境坑**：后端 CORS 只放行 `http://localhost:5173`，用 `http://[::1]:5173` 访问时 `POST /paper/upload` 直接 403（"Invalid CORS request"），页面会提示"3 篇未能提交（403）"。
