## 一、交付内容

### 1. 内置模板预设

新增 `backend/src/main/java/com/graduate/thesis/service/PresetTemplateService.java`，把校规固化为可复用的内置预设：

| 常量 | 值 |
| --- | --- |
| `GUILIN_PRESET_KEY` | `guilin-institute` |
| `GUILIN_TEMPLATE_NAME` | `桂林信息科技学院毕业论文格式` |

预设同时提供 4 段配置 JSON（`page_config` / `heading_patterns` / `toc_config` / `reference_config`）与 7 条格式规则（heading1~3、body、figure、table、tableText）。

### 2. 新用户自动建档

`UserService.register()` 在用户落库、绑定角色之后调用 `PresetTemplateService.provisionForNewUser(userId)`：

- 独立事务（`REQUIRES_NEW`），模板创建失败**不阻断注册**；
- 幂等：同名模板已存在则跳过；
- 已验证：注册新账号后自动获得 1 份模板 + 7 条规则。

## 二、测试方法

以真实论文为底本，用脚本构造 10 个「打乱」场景，逐个走完整的 HTTP 排版链路（上传 → 创建任务 → 轮询 → 下载产物），再用 lxml 解析产物 `document.xml` 逐项核对格式。

| 场景 | 模拟的真实情况 |
| --- | --- |
| `s1_baseline` | 原始文档直接排版（基线） |
| `s2_no_toc` | 学生删掉了自动目录 |
| `s3_plain_toc` | 目录是手打的纯文本（带点线，无 Word 域） |
| `s4_text_numbered` | 标题编号写成正文文本（1 / 1.1 / 1.1.1） |
| `s5_flat_style` | 从 PDF 复制粘贴，Heading 样式全部丢失 |
| `s6_captions` | 图表题注写法混乱（图1-1 / 图 2.1 / 表 2-2） |
| `s7_english_mix` | 正文中英混排 |
| `s8_refs_messy` | 参考文献序号风格混乱（[1] / 1. / (1) / 1、） |
| `s9_no_tail` | 删除了谢辞与参考文献 |
| `s10_edge` | 超长标题 + 纯数字段落 + 空段落 |

## 四、发现并已修复的问题

| # | 问题 | 根因 | 影响 |
| --- | --- | --- | --- |
| P1 | 排版任务永久卡在「处理中 0%」，永不结束 | `TaskScheduler.dispatch()` 先 CAS 把任务从 PENDING 改为 PROCESSING，随后 `PaperService.runFormat()` 又要求 PENDING→PROCESSING，第二次 CAS 必然失败直接 return | **功能整体不可用**。已改为同时接受 PENDING / PROCESSING |
| P2 | 图表题注行距恒为 1.5 倍，不读模板 | `CaptionFormatter` 里把 `w:spacing` 写死为 360 auto | 与「固定值 20 磅」校规冲突。已改为按规则生成 exact/multiple |
| P3 | 有序号的参考文献被合并成一整段 | `REF_ITEM_START` 用 `matches()` 全串匹配，正则却以 `\s*` 结尾（无 `.*`），编号后只要还有正文就永远 false，「续行合并」把后续条目全部吞并 | 9 条文献变成 1 段。已在正则末尾补 `.*` |
| P4 | 无序号参考文献完全不处理 | `REF_NUM` 不匹配即 `continue`，而学生论文里绝大多数文献列表本来就没有序号 | 参考文献区完全没排版。已新增 GB/T 7714 类型标识（`[J]/[M]/[C]/[D]/[P]/[S]`）识别并自动补号 |
| P5 | `page_config` 里一旦出现 `abstract`/`section` 节点，整份页面配置被丢弃回退默认值 | `RuleSet.from()` 用裸 `ObjectMapper` 反序列化 `PageConfig`，未知字段抛异常被 `catch` 吞掉 | 表现为「配了 2.5cm 却排成默认 3cm」。已关闭 `FAIL_ON_UNKNOWN_PROPERTIES` |
| P6 | 字号只能存整数磅，「五号 10.5pt」无法表达 | `FormatRule.fontSize` / `RuleSaveDTO.fontSize` 为 `Integer`，`t_format_rule.font_size` 为 `INT` | 图表题注与参考文献被迫取 10pt。已改为 `Double` + 列类型 `DOUBLE`，前端字号表补 10.5 |

> P1 是本轮测试最先撞上的问题：不修它则无法产生任何排版产物。P5、P6 是在落模板配置时暴露的，会直接影响成品精度，故一并修复。

## 五、遗留问题与建议

| # | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| L1 | 标题样式丢失时（`s5`）引擎识别不到任何标题，且 `report` 里 `chapterCount=0`、`suspects=[]`，**不给出任何提示** | 用户以为排版成功，实际正文未按标题层级处理 | 结构识别兜底：正文段落若"短行 + 无标点 + 独占一段"可提示"疑似标题"；至少在报告里给出"未识别到章节标题"的显式警告 |
| L2 | 正文标题不自动补编号 | 原文标题无编号时，正文是「绪论」，目录却是「1 绪论」，两者不一致 | 引擎增加"按 heading 层级自动编号"能力（1 / 1.1 / 1.1.1），可由模板开关控制 |
| L3 | 题注编号不规范时不纠正 | `图 2.1`、`图3-1`（缺空格）原样保留，与「图1-1」规范不一致 | `CaptionFormatter` 解析出章节号与序号后，统一按 `numberingPattern` 重写 |
| L4 | 参考文献条目行距只能设倍数 | `ReferenceConfig.lineSpacing` 仅支持倍数，无法满足「固定值 20 磅」 | 增加 `lineSpacingType` / `lineSpacingExact` 字段 |
| L5 | 文献悬挂缩进 `hanging=420` twips（约 0.74 字符） | 第二行未与序号后文字严格对齐（规范要求悬挂到序号之后） | 按实际序号宽度（`[1]  ` ≈ 640 twips）动态计算 |
| L6 | 摘要标题、关键词标签被加粗 | 校规只写「三号字、黑体、居中」，未要求加粗；黑体再加粗会显得过重 | 预设里把 `zhTitleBold`/关键词加粗改为 false（Abstract 仍保留加粗，校规明确要求"加黑"） |
| L7 | 表格单元格内段落残留 `firstLine=420` 缩进 | 表格文字未完全归一 | `applyTableCells` 显式清零首行缩进 |
| L8 | 个别新增英文 run 未套字体 | 少量英文可能是宋体而非 TNR | 排版结束后统一遍历正文 run 补 `rFonts` |

## 六、结论

- 模板已按校规逐条落地，**19 项关键格式检查全部通过**，包括最容易出错的页边距、20 磅固定行距、三级标题字体体系、目录字号与数字字体、图表题注五号字与位置、参考文献自动编号与悬挂对齐。
- 10 个打乱场景全部排版成功，说明引擎对「无目录 / 纯文本目录 / 文本编号 / 无尾部章节 / 超长标题」等真实变体有较好鲁棒性。
- 本轮共修复 6 个问题，其中 P1（任务卡死）、P3（文献合并）属于阻断级缺陷，修复前系统实际上无法完成一次完整排版。
- 仍存在的问题集中在两处：**结构识别的兜底与提示（L1/L2）**、**引擎写死参数未完全配置化（L3~L5）**。这两类不阻断使用，但会影响成品与校规的严格一致性。

## 七、复现方式

```bash
# 1. 生成 10 个测试场景（依赖 python-docx）
python tmp_v3/gen_cases.py

# 2. 注册测试账号并自动建档（JUnit，断言模板与 7 条规则）
cd backend && mvn -o test -Dtest=PresetProvisioningTest

# 3. 逐场景排版并下载产物
python tmp_v3/run_cases.py

# 4. 解析产物核对格式
python tmp_v3/analyze.py
```

产物目录：`tmp_v3/out/*_out.docx`；格式聚合结果：`tmp_v3/analyze.json`。
